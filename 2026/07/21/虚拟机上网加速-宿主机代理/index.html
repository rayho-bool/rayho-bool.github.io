虚拟机上网加速：通过宿主机代理让 Ubuntu Server 用上梯子

发表于2026-07-21|更新于2026-07-21|运维
|总字数:1.5k|阅读时长:5分钟|浏览量:

最近在 VMware 里装了个 Ubuntu Server 虚拟机跑开发环境，结果发现从 GitHub 拉代码简直龟速——git clone 只有 22 KiB/s，还时不时 Connection refused。但宿主机的 Windows 上开着梯子，浏览器访问 GitHub 秒开。于是研究了一下怎么让虚拟机共享宿主机的”加速通道”，过程比想象中简单，记录一下供大家参考。

为什么要这样折腾？

虚拟机网络通常通过 NAT 或桥接模式上网。如果宿主机直连 GitHub 本身很快，那虚拟机也不会有问题；但实际情况往往是宿主机也要依赖代理才能流畅访问外网，而虚拟机默认并不会自动继承这个代理。

核心思路：在宿主机上把代理共享出来，让虚拟机里的流量指向宿主机 IP 的代理端口。所有请求先走到宿主机，再由宿主机的梯子转发出去，从而绕过虚拟机的网络限制。

准备工作：让宿主机代理”对外营业”

无论你用 Clash、v2rayN、Shadowsocks 还是其他工具，都需要打开 Allow LAN（允许局域网连接） 功能，并记下代理端口。

  • Clash：默认 HTTP/SOCKS5 端口通常为 7890，在 General 里打开 “Allow LAN”。
  • v2rayN：默认 SOCKS5 端口 10808，HTTP 端口 10809，需要在”参数设置”里勾选”允许来自局域网的连接”。
  • Shadowsocks：默认端口 1080，勾选”允许其他设备连入”。

我的环境是 Clash，HTTP 代理地址在宿主机本机上是 127.0.0.1:7890，开启 LAN 后，其他设备就可以通过宿主机 IP 加这个端口来使用代理。

常见坑及解决

1. 虚拟机 ping 不通宿主机 IP
通常是 Windows 防火墙拦截了。可以暂时关闭防火墙测试，或者为代理端口添加入站规则（允许来自 192.168.xxx.0/24 的访问）。

2. 确认代理端口正确，但 curl 报 Connection refused
检查宿主机代理软件是否确实打开了 Allow LAN；有些梯子开启 LAN 后还需要重启软件。或者端口号写错了，HTTP 代理端口和 SOCKS5 端口可能不同。

3. 速度没提升，甚至打不开网页
可能是代理节点本身较慢，换一个节点试试；或者代理协议不匹配（比如配置里写了 HTTP 但实际只支持 SOCKS5）。用 curl -v https://github.com 能看到详细的代理交互过程，便于诊断。

4. 环境变量只对当前终端有效
如果你希望长期生效，可以把 export 命令写入 ~/.bashrc 或 ~/.zshrc，但要注意这会让终端下所有工具都走代理，可能访问局域网服务时会变慢。更推荐的方式是单独配置 Git 的代理，或者写个函数来开关代理。

最后

整个方案的核心其实就是 “宿主机开共享 + 虚拟机填地址” 两步。虽然每次开机代理 IP 可能变化（特别是 DHCP 环境），但 NAT 模式下网关 IP 相对固定，用起来很稳定。这套方法也适用于 WSL2、Docker 容器等场景，希望对你有所帮助。

如果还有更好的技巧或踩坑经验，欢迎在评论区交流。
