VMware Ubuntu Server 搭建 Samba 共享文件夹，Windows 与虚拟机双向互传文件

发表于2026-07-20|更新于2026-09-16|运维
|总字数:1.3k|阅读时长:4分钟|浏览量:

前言

日常使用 VMware 运行 Ubuntu Server 时，经常需要在 Windows 宿主机和虚拟机之间传输代码、配置文件、安装包。VMware 自带的 /mnt/hgfs 共享虽然简单，但存在大文件读写卡顿、Linux 文件权限丢失、稳定性差等问题。Samba 基于局域网文件共享协议，速度稳定、权限可控，适合长期开发和运维场景使用。本文完整记录从零配置 Samba 的全部步骤与排错方案。

两种文件共享方案对比

方案 优点 缺点 适用场景
VMware hgfs 共享 配置极简，一键开启 大文件 IO 速度慢、Linux 权限失效、偶尔挂载丢失 临时传输少量小文件
Samba 局域网共享 传输速度稳定、读写权限自定义、Windows 原生网络访问 需要手动配置服务与账号 长期开发、大量文件互传、项目代码同步

六、常见故障排查

1. Windows 无法找到共享主机

  • 虚拟机网卡网络模式设置为 NAT，不要使用仅主机模式
  • 检查服务运行状态：systemctl status smbd
  • 临时关闭 Windows 专用网络防火墙后重试

2. 能看到文件夹但无法写入

  • 重新给共享目录开放权限：chmod 777 ~/share
  • 确认 smb.conf 中 read only = no 配置无误，重启服务生效

3. 账号密码持续验证失败

  • 重新执行 sudo smbpasswd -a rayho 重置 Samba 密码
  • Windows 登录框仅填写纯用户名，不要携带 IP 或域名前缀

如果只是临时传输少量小文件，可使用 VMware 自带共享：

VMware 操作：虚拟机设置 → 选项 → 共享文件夹 → 添加 Windows 本地目录，选择「总是启用」。虚拟机内自动挂载至 /mnt/hgfs/。

方案局限

  • 大文件批量传输读写卡顿，IO 性能差
  • Windows 复制到虚拟机的文件会丢失 Linux 权限与软链接特性
  • 虚拟机重启后偶尔出现挂载失效

总结

  1. 长期开发、大量文件同步优先选择 Samba 共享，稳定性与速度最优
  2. Samba 密码独立于系统用户，配置完成后务必放行防火墙并重启服务
  3. Windows 访问依赖虚拟机内网 IP，推荐映射网络驱动器简化日常使用
  4. 遇到连接或权限问题，优先检查配置文件语法、目录权限、防火墙规则三点
