Git 常用命令手册

面向日常开发。按”我要做什么”组织，不按命令字母表排。
约定：<xxx> 是占位符，尖括号本身不要输入。

0. 一次性配置

注意：--global 写到 ~/.gitconfig；不加则只作用于当前仓库（写 .git/config）。仓库级配置优先级更高。

2. 日常主线：改 → 存 → 提

--amend 只改本地未推送的提交，推过的会被改写，慎用。

4. 分支

switch vs checkout：checkout 一个命令干三件事（切分支、还原文件、切提交），容易误伤。Git 2.23+ 拆成 switch（切分支）和 restore（还原文件），建议用新命令。

5. 远程协作

pull 冲突了怎么办：解冲突 → git add <冲突文件> → git commit（rebase 模式下是 git rebase --continue）。想反悔：git merge --abort 或 git rebase --abort。

8. 变基 rebase

把当前分支的提交”搬”到另一个基点上，历史变成一条直线。

交互式 rebase 里的指令：

指令 作用
pick 保留该提交
reword 保留但改提交信息
edit 停下来修改该提交内容
squash 合并到上一个提交，提交信息合并
fixup 合并到上一个提交，丢弃本条信息
drop 删掉该提交

铁律：只对自己本地、没推送过的提交做 rebase。改公共分支历史 = 给所有人添麻烦。

忽略文件规则

11. 危险等级速查

命令 危险度 说明
git restore <file> 高 丢弃未提交改动，不可恢复
git reset --hard 高 丢弃提交和改动，reflog 可救
git clean -fdx 高 删文件，不进回收站
git push --force 极高 覆盖远程历史，别人工作可能丢
git push --force-with-lease 中 力推的安全版，远程被别人改过会拒绝
git rebase 公共分支 高 改写他人历史
git branch -D 中 未合并分支直接删
git revert 低 安全，只是新增提交
git stash 低 安全，可恢复

12. 一条命令看懂当前状况

日常起手式：先 git status，再看 git diff，然后才动手。90% 的 git 事故源于没看清状态就敲命令。
